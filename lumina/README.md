# LUMINA — 기니피그 친구들의 소풍 게임 모음

기니피그 친구들(휘기·기니니·뽀니·모카)과 소풍 담요 위에서 하는 게임 모음입니다. 테이블 건너편에는 3D 기니피그들이 앉아 같이 둡니다.

**게임 사이트**: https://sonny4984.github.io/claude-trade-backend/ (검색에는 안 나오게 해 두었습니다)

- **루미큐브** (Rummikub Classic 공식 규칙): 혼자(AI 1~3명, 네 단계: 입문·보통·고수·명인), 함께(폰 하나를 돌려 가며, 차례마다 가림막), 온라인(힌트 없음). 끌어 놓기 말고도 **누르고 놓기**(타일을 누른 뒤 세트나 빈 탁자를 누름), 세트 곁에 놓으면 붙기, 777(숫자끼리)·789(색 차례) 정렬 단추.
- **다빈치 코드**: 흑·백 숫자 타일의 숨은 코드를 추리합니다. 보드게임처럼 뒷면으로 펼친 더미에서 원하는 색(검정·하양)을 골라 가져옵니다(처음 4장, 차례마다 1장). 혼자·함께·온라인.
- **오목**: 흑 쌍삼 금지(한국식, 끌 수 있음), AI 네 단계, 무르기·힌트, 온라인.
- **불과 얼음**: 둘이 힘을 합쳐 탈출하는 협동 퍼즐 플랫폼 게임입니다. 34단계(웅덩이·버튼·레버 승강기 → 크림 선반·젤리·불꽃/고드름 커튼 → 방탈출처럼 머리 쓰는 쿠키 열쇠·자물쇠, 순간이동 구멍, 젤리빈 문·거꾸로 문 → 모두 섞은 대탈출 → 풀이기로 찾아낸 두뇌 단계 7개, 순간이동 구멍 복도, 미리 레버를 맞춰 두는 두 층 금고), 별 세 개(통과·사탕 모두·시간 안에). 모든 단계를 바로 고를 수 있고 처음엔 안 깬 첫 단계부터 이어서, 온라인 방에서는 서로 깬 단계를 합쳐 저장합니다. 혼자(불·얼음 번갈아), 한 기기 둘이(방향키·WASD 또는 양손 터치), 온라인. **셋이서**: 말차 기니피그(말차 늪이 안전)가 더해지는 단계 2개 — 혼자 셋을 번갈아, 또는 온라인 셋(방장 불·둘째 얼음·셋째 말차). **힌트(H)·막힘 알림**: 지금 상태를 풀이기(따로 도는 작업자)로 풀어 다음 한 수를 반짝여 주고, 통과할 수 없게 되면 알려 줍니다.
- **전체 화면**: 홈 화면에 추가하면 주소창 없이 앱처럼 열립니다(manifest·아이콘). 안드로이드·PC는 메뉴의 "전체 화면" 버튼으로 바로, 아이폰은 버튼을 누르면 "홈 화면에 추가" 방법이 나옵니다. 게임 중에는 길게 눌러도 글씨가 선택되지 않습니다.
- **온라인 대전**: 로그인 없이 **초대 링크 하나**로 친구와 바로 같이 합니다. 아래 "온라인 대전" 참고.
- **채팅·음성**: 온라인 방(대기실·게임 중)에서 방 코드 옆 말풍선 단추로 글 채팅·빠른 말("꾸잉!", "지금!", "버튼 밟아 줘" 등)을 주고받고, "음성 켜기"로 목소리로도 이야기합니다. 글은 방의 암호화 채널로, 음성은 브라우저 WebRTC로 기기끼리 바로 잇습니다(연결 신호만 암호화 채널로). 모바일 데이터처럼 바로 이어지지 않는 망은 TURN 중계가 있어야 해서, `.env`에 `VITE_TURN_URLS`·`VITE_TURN_USER`·`VITE_TURN_PASS`를 적거나 임시 비밀번호를 내주는 주소를 `VITE_TURN_API`로 적으면 씁니다. 게임·대기실에서는 화면이 꺼지지 않게 잡아 둡니다(Screen Wake Lock).
- **규칙 배우기**: 루미큐브 여섯 걸음 튜토리얼입니다. 실제 타일을 움직여야 다음으로 넘어갑니다.
- **기타**: 힌트 3단계, 되돌리기·다시, 작업대, 9개 테마(기본은 "피크닉"), 기록·통계, 9:16 결과 카드, 한국어·영어를 지원합니다.

## 실행

```bash
npm install            # .npmrc에 legacy-peer-deps=true
npm run dev            # 개발 서버 (http://localhost:5173)
npm run build          # 타입 검사 + 배포용 빌드 → dist/
npm run build:single   # JS·CSS를 index.html 하나로 → dist-single/ (게임 사이트·claude.ai 아티팩트용)
npm run preview        # 빌드 결과 미리보기 (http://localhost:4173)
```

**게임 사이트 올리기 (GitHub Pages)**: `npm run build:single`로 만든 `dist-single/index.html`을 `gh-pages` 브랜치의 `index.html`과 `404.html`로, `dist-single/manifest.webmanifest`와 `dist-single/icons/`도 그대로 올리면 몇십 초 뒤 사이트가 바뀝니다(`.nojekyll`, `robots.txt`도 같은 브랜치에 있음). 같은 파일들을 `site/`에도 복사해 둡니다. 홈 화면 아이콘은 `npx tsx scripts/make-icons.ts`로 게임의 그리기 코드에서 다시 만듭니다. 초대 링크에 들어갈 사이트 주소는 `.env`의 `VITE_PUBLIC_URL`입니다(한 파일 빌드는 `--mode single`이라 `.env.production`이 아니라 `.env`에 둡니다).

`vercel.json`에 SPA 리라이트가 들어 있어 Vercel에 그대로 올릴 수도 있습니다.

주소 뒤에 `?seed=숫자`를 붙이면 같은 판(타일 섞기와 AI 판단)을 다시 둘 수 있습니다. 테스트에서도 이 기능을 씁니다.

## 테스트

```bash
npm test               # 규칙 커널·솔버·AI·다빈치 코드·오목·불과 얼음·온라인 중계 단위 테스트 (Vitest, 264개)
npm run sim -- 10000   # AI끼리 1만 판 — 불법 수·타일 보존 위반을 센다
npm run test:e2e       # 실제 브라우저로 하기 (Playwright, 폰·데스크톱 + 온라인 두 기기)
npx tsx scripts/bench-solver.ts   # 솔버 속도
npx tsx scripts/find-seed.ts      # E2E용 시드 찾기
npx tsx scripts/coda-sim.ts       # 다빈치 코드 AI끼리 대전
npx tsx scripts/online-check.ts   # 온라인 E2E 시드, 방 문서 크기
npx tsx scripts/fi-debug.ts [단계]  # 불과 얼음: 단계가 풀리는지, 원소별로 닿는 칸 그림
npx tsx scripts/fi-bot.ts [단계]    # 불과 얼음: 풀이를 실제 물리로 따라가 보기
npx tsx scripts/fi-shots.ts <폴더>  # 불과 얼음 화면 캡처 (미리보기 서버 필요)
npx tsx scripts/fi-try.ts <초안.json> [id]  # 불과 얼음 단계 초안 점검 (풀리는지·사탕·로봇 재생·닿는 칸 그림)
```

E2E 테스트는 `playwright.config.ts`가 빌드와 미리보기 서버를 알아서 띄웁니다. 미리 깔린 Chromium이 있으면 그걸 쓰고, 경로는 `PW_CHROMIUM` 환경 변수로 바꿀 수 있습니다. 3D 무대는 SwiftShader(소프트웨어 WebGL)로 그립니다.

온라인 E2E(`e2e/online.spec.ts`, `e2e/fireice.spec.ts`)는 브라우저 컨텍스트 두 개(방장 기기·친구 기기)를 띄우고, 테스트 프로세스 안의 MQTT 서버(`e2e/broker.ts`, aedes)로 잇습니다. 앱은 주소에 `?broker=ws://127.0.0.1:포트`가 있으면 공개 중계 서버 대신 그 서버를 씁니다(localhost에서만 받아들임). 불과 얼음 캔버스 속 위치는 localhost에서만 열리는 시험용 손잡이 `window.__fireice`로 읽습니다.

## 엔진 구조

- **판정은 커널만 합니다**: UI는 "이렇게 두고 싶다"를 제안만 하고, `reduce()`가 공식 규칙으로 판정합니다. 커널은 DOM·시간·난수에 직접 기대지 않습니다(난수는 시드가 있는 mulberry32).
- **차례 트랜잭션**: 차례가 시작되면 테이블과 랙의 작업 사본을 만듭니다. 그 안에서는 자유롭게 옮기고 나누고 합칠 수 있고(되돌리기·다시 무제한), 검사는 "내기"를 누를 때만 합니다. 틀리면 문제 있는 세트와 이유를 표시합니다.
- **공식 규칙** (rummikub.com 규칙서 2019판 기준):
  - 첫 등록은 손패만으로 30점 이상이어야 합니다.
  - 테이블 타일은 랙으로 되가져올 수 없습니다.
  - 조커는 테이블 안에서 자유롭게 풀 수 있습니다.
  - 시간이 다 되면 올바른 상태는 그대로 내고, 틀린 상태면 되돌린 뒤 3장을 뽑습니다(아무것도 안 했다면 1장).
  - 남은 조커는 30점으로 셉니다.
  - 더미가 비면 남은 타일 점수로 승부합니다.
  - 카페 하우스 룰(등록 후 계속 두기 등)은 대국 준비에서 켤 수 있습니다.

## AI 구조

- **솔버**는 숫자 1→13 순서의 동적 계획법입니다. 색마다 열린 런 상태(1장/2장/3장 이상)와 조커 사용, 그룹 조합을 상태로 둡니다. 앞으로 필요한 타일 수를 미리 따져 가지를 잘라서 p99 약 0.13초에 풉니다.
- **AI 성격**은 같은 솔버를 쓰되 보는 범위와 실수가 다릅니다.

  | 단계 | 이렇게 둡니다 |
  | --- | --- |
  | 입문 | 손패끼리만 조합하고, 테이블을 다시 짜지 않습니다. 조커를 바로 쓰고, 둘 수 있는 수를 가끔(18%) 놓칩니다 |
  | 보통 | 넉넉한 세트(4장 그룹, 4장 이상 런)만 고쳐 붙입니다. 조커를 아끼고 가끔(5%) 놓칩니다 |
  | 고수 | 테이블 전체를 다시 짭니다. 첫 등록은 필요한 만큼만 냅니다 |
  | 명인 | 고수처럼 두면서, 상대가 3장 이하로 줄면 조커와 큰 숫자부터 털어 냅니다 |

- 생각 시간은 단계마다 다릅니다. 입문은 0.6~1.2초, 명인은 1.5~2.8초이고, 설정에서 빠르게·느리게로 바꿀 수 있습니다.
- AI가 낸 타일은 그 캐릭터의 앞발에서 테이블로 날아갑니다.

## 디자인 시스템

- `src/styles/picnic.css`: 기본 테마 **피크닉**입니다. 크림색 풀밭 위 발자국 무늬, 민트 깅엄 담요와 흰 바늘땀, 꿀색 원목 레일, 딸기·블루베리·당근·코코아 잉크를 씁니다. 버튼은 아래쪽 두께가 있어 누르면 쏙 들어가는 말랑한 알약 모양이고, 글꼴은 주아·고운돋움·Fredoka입니다.
- `src/styles/tokens.css`: 모든 색·재질·움직임을 CSS 변수로 둡니다. 변수의 기본값은 "루미나" 테마(저녁 펠트·호두나무·황동·상아)입니다.
- `src/styles/themes.css`: 나머지 테마는 색만 바꾸는 게 아니라 테이블·랙·타일 재질과 그림자·강조색까지 바꿉니다. 루미나, 클래식 아이보리, 미드나잇, 내추럴 우드, 모던 글래스, 미니멀 스튜디오, 소프트 파스텔, 코지 말차가 있습니다.
- 예전 기본 테마(루미나)를 쓰던 저장값은 처음 한 번만 피크닉으로 옮깁니다(`themeRev`). 설정에서 언제든 되돌릴 수 있습니다.
- 접근성:
  - 색 구분 모양 표시: 빨강 ●, 파랑 ◆, 주황 ▲, 검정 ■
  - 고대비, 색각 보조 팔레트, 움직임 줄이기
  - 키보드 조작: 숫자로 고르기, N 새 세트, U 되돌리기, D 뽑기, H 힌트, S 정렬, Space 내기
  - 스크린리더 라벨

## 3D 캐릭터와 에셋 교체

모든 그래픽은 코드로 만듭니다. 이미지·3D 모델·오디오 파일이 없습니다.

- **캐릭터 모양**: `src/stage/guinea.ts`
  - 몸·머리·갈기·앞발·나비넥타이를 구(球)를 늘여 만든 셀 셰이딩 모델입니다.
  - 테이블 뒤에 앉은 것처럼 보이도록 레일 선 아래를 잘라 냅니다.
- **캐릭터 얼굴**: `src/characters/draw2d.ts`의 `drawFace()`가 캔버스에 그립니다.
  - 이 그림을 3D 머리 앞면 텍스처로 붙이고, 2D 초상화에도 같이 씁니다.
- **캐릭터 목록**: `src/characters/roster.ts`에 털 모양, 눈썹, 주둥이 패치, 안경, 나비넥타이 색이 있습니다.
- **다른 캐릭터로 바꾸기**:
  1. `roster.ts`에 새 항목을 추가합니다.
  2. `drawFace()`에 얼굴을 추가합니다.
  3. `guinea.ts` 생성자에서 모양을 추가합니다.
  - GLB 모델을 쓰려면 `Guinea` 클래스에서 모델을 불러오도록 바꾸면 됩니다. 무대(`scene.ts`)는 `root`, `headTop`, `react()`, `update()`만 씁니다.
- **3D 초상화**: `src/stage/portraits.ts`가 같은 모델을 화면 밖에서 찍어 홈·대국 준비·결과·결과 카드에 씁니다. WebGL이 없거나 설정에서 3D를 끄면 2D 그림으로 대신합니다.
- **효과음**: `src/audio/sfx.ts`에서 소리마다 합성 함수를 오디오 파일 재생으로 바꾸면 됩니다.
- **글꼴**: `index.html`에서 Google Fonts(Fredoka, Jua, Gowun Dodum, Fraunces, Instrument Serif, Figtree, IBM Plex Sans KR)를 불러옵니다. 오프라인이면 시스템 글꼴로 대신합니다.

## 온라인 대전

한국 모바일 게임처럼 **방을 만들고 → 카카오톡으로 링크를 보내고 → 친구가 링크를 누르면 바로 입장**합니다. 로그인·계정·공유 설정이 필요 없습니다.

**친구 부르기**
1. 방장: 홈 → **온라인 대전** → 캐릭터·이름 → 게임(루미큐브·다빈치 코드·오목·불과 얼음) → **방 만들기**.
2. **카카오톡으로 초대하기**를 누르면 폰의 공유 창이 열립니다(카카오톡 선택). 공유 창이 없는 기기에서는 링크가 복사됩니다.
3. 친구가 링크를 누르면 게임 사이트가 열리고, 이름만 확인하고 **입장**하면 끝입니다. 링크 대신 6자리 방 코드를 **친구 방에 들어가기**에 입력해도 됩니다.
4. 방장이 (루미큐브·다빈치 코드·오목이면 빈자리에 AI를 앉히고) **시작하기**를 누릅니다.

**구조**
- 서버를 따로 두지 않고 공개 MQTT 중계 서버(WebSocket, `wss://`)를 우편함처럼 씁니다. 차례로 시도: shiftr.io 공개 서버 → EMQX 공개 서버 → HiveMQ 공개 서버. 초대 링크에는 방장이 붙은 서버 번호(`b=`)가 같이 들어갑니다.
- 방 코드(6자리)에서 PBKDF2로 암호 키와 주제 이름을 만들고, 모든 메시지를 AES-GCM으로 암호화합니다. 중계 서버는 방 코드를 모르면 내용을 볼 수 없습니다.
- **방장 중심**: 판 판정·AI 차례·점수는 방장 기기의 커널이 합니다. 판 전체는 "방 문서"(보존 메시지) 하나에 들어가 늦게 들어온 친구도 받습니다. 참가자는 자기 수만 보내고(`act`), 방장이 검증해 새 문서를 씁니다(`seq` + 1). 틀린 수는 `reject`로 알려 줍니다.
- **불과 얼음**은 실시간이라 몸 위치를 초당 12번까지 빠른 순간 메시지(`fp`)로 (가만히 있으면 1초에 한 번) 주고받고, 사탕·레버·넘어짐은 확실한 메시지(`fe`)로, 단계·다시 하기·통과는 방장이 방 문서로 알립니다. 방장이 불, 친구가 얼음입니다.
- 누가 들어와 있는지는 presence(이름·캐릭터, 끊기면 서버가 지움)로 봅니다. 연결이 끊긴 친구 자리는 방장이 "AI가 대신 두기"로 넘길 수 있고(불과 얼음 제외), 같은 기기로 다시 들어오면 자리를 되찾습니다. 방장이 새로고침해도 "방으로 다시 들어가기"로 이어서 돌립니다.
- claude.ai 아티팩트 안에서는 링크를 나눌 수 없으므로, 온라인 화면에 게임 사이트로 가는 버튼을 보여 줍니다.

## 불과 얼음 단계 만들기

단계는 `src/fireice/levels.ts`에 가로 16 × 세로 20 글자 지도로 적습니다. 글자 뜻은 `src/fireice/level.ts` 머리말에 있습니다(`#` 블록, `L` 딸기잼, `W` 블루베리 물, `G` 말차, `f`/`i` 시작, `F`/`I` 문, `r`/`b` 사탕, `1`·`2` 버튼, `3`·`4` 레버, `=` 크림 선반, `J` 젤리, `H` 불꽃 커튼, `C` 고드름 커튼, `5`~`8` 젤리빈 문, `x`·`y` 거꾸로 문, `k` 열쇠, `K` 자물쇠, `@`·`%` 순간이동 구멍 한 쌍). 움직이는 발판은 `platforms`에 쉴 때 자리와 켜졌을 때 옮겨 갈 칸 수로 적습니다(세로로 서 있는 문처럼 w=1, h=3도 됨). 초안은 JSON 목록으로 적어 `scripts/fi-try.ts`로 바로 점검할 수 있습니다.

새 단계는 두 가지로 검사합니다(`src/fireice/__tests__/fireice.test.ts`).
1. **칸 모형 BFS**(`verify.ts`): 두 캐릭터·레버 상태를 한꺼번에 찾아, 둘 다 문에 설 수 있는지와 사탕을 모두 먹을 수 있는지 봅니다. 점프는 실제보다 보수적으로 봅니다(위로 3칸이면 옆으로 2칸 등, 머리 위 한 줄 여유 필요, 천장이 낮으면 덜 멀리). 젤리는 약 5칸까지 튀는 것으로 봅니다. 열쇠는 함께 쓰는 개수로, 자물쇠·문·순간이동도 상태에 넣습니다. 레버 칸을 걸어서 지나가면 그쪽으로 밀린다는 것(오른쪽 켬, 왼쪽 끔)도 넣습니다. `verifyLevel(…, analyze)`는 되돌릴 수 없이 막히는 상태의 비율도 셉니다.

**두뇌 단계 찾기**(`scripts/fi-search.ts`): 검증된 지도 틀에 문 자리(젤리빈 문·거꾸로 문 등)를 비워 두고, 여러 조합을 실제 풀이기로 풀어 레버 조작 수·막다른 상태 비율·걸음 수가 큰 판을 고릅니다. 24·34단계(교대 근무, 뚜껑 문)가 이렇게 찾은 판입니다(레버 6번·막다른 상태 46%, 레버 4번·58%).
2. **실제 물리 재생 로봇**(`__tests__/bot.ts`): 칸 모형이 찾은 가장 짧은 풀이를 실제 물리로 한 걸음씩 따라가 문까지 가는지 봅니다.

레버는 오른쪽으로 밀면 켜지고 왼쪽으로 밀면 꺼지므로, 켠 뒤 되돌아와야 하는 벽 끝에는 두지 않습니다.

## 알려진 한계

- 온라인 대전은 무료 공개 중계 서버에 기댑니다. 서버가 붐비거나 멈추면 연결이 늦거나 끊길 수 있습니다(다른 서버로 자동 재시도, "다시 연결" 버튼).
- 방 코드를 아는 사람은 판 내용을 풀어 볼 수 있습니다(방 문서에 모든 패가 들어 있음). 친구끼리 하는 것을 전제로 합니다.
- 방장 기기가 판을 돌리므로 방장이 나가면 방이 닫히고, 방장이 오래 자리를 비우면 모두 기다려야 합니다.
- 불과 얼음 온라인은 서로의 위치를 따라가며 보여 주므로, 통신이 느리면 친구 캐릭터가 조금 늦게 보입니다. 버튼·발판은 각 기기가 따로 계산합니다.
- 3D 무대는 WebGL이 필요합니다. 없으면 2D 자리표로 자동 전환됩니다.
- 효과음은 합성음이라 실제 타일 소리와는 다릅니다.
